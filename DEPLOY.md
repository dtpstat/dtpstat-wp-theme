# Обновление только темы `dtpstat-child`

Эта инструкция описывает `bin/deploy.sh` — **выполнение с рабочей машины через SSH/rsync**. Скрипт не устанавливает WordPress, не импортирует записи и медиа, не меняет БД и не запускает серверный установщик `bin/install.sh`.

Для первоначальной установки или замены контента пользуйтесь [INSTALLER.md](INSTALLER.md). Для связки с фронтендом карты — [SETUP.md](SETUP.md).

## Перед запуском

Откройте `bin/deploy.sh` и проверьте три переменные в его начале:

| Переменная | Назначение |
|---|---|
| `HOST` | SSH-алиас либо адрес целевого сервера |
| `WP_PATH` | Путь **к каталогу темы** `wp-content/themes/dtpstat-child` на сервере; относительный — от домашнего каталога SSH-пользователя |
| `WP_CLI` | Команда WP-CLI для сброса кэша на сервере; текущий пример использует PHP и `~/wp-cli.phar` |

Проверьте, что SSH авторизуется, у пользователя есть права записи в каталог темы, а команда WP-CLI соответствует целевой установке. Настройки в скрипте — **специфичны для конкретного сервера**; не считайте значения по умолчанию универсальными.

### ВНИМАНИЕ: синхронизация с удалением

`bin/deploy.sh` выполняет `rsync -az --delete` на **каталог темы назначения**. Любые дополнительные файлы в этом каталоге, отсутствующие в `theme/dtpstat-child/` репозитория, будут удалены. Скрипт не создаёт резервной копии и не поддерживает автоматический откат.

Перед применением на рабочем сайте выполните пробную синхронизацию с теми же адресом и путём, что указаны в скрипте, например:

```bash
# Подставьте реальный HOST и WP_PATH из bin/deploy.sh:
rsync -azn --delete --itemize-changes \
  theme/dtpstat-child/ \
  'dtpstat:wp/wp-content/themes/dtpstat-child/'
```

Здесь `-n` означает dry-run. Сверьте список удалений и изменений до реального запуска. Если состояние темы критично, отдельно сохраните её текущую версию и проверьте возможность восстановления.

## Выкладка

Из корня репозитория:

```bash
./bin/deploy.sh
```

Скрипт копирует файлы темы и выполняет попытку `wp cache flush`. Ошибка сброса кэша **подавляется скриптом**; сообщение «Тема обновлена» подтверждает только выполнение rsync и SSH-команды, но **не** валидирует работу сайта или сброс кэша.

После выкладки проверьте страницы и PHP-журнал WordPress. Тема должна быть установлена и активирована заранее.

## Конфигурация темы: только сгенерированные PHP-константы

**До выкладки темы обязательно создайте**
`WP_CONTENT_DIR/dtpstat-config.php` через
`bin/generate-config.py` из проектного `<repo>/.env`.
Например, для WordPress в `/var/www/wp`:

```bash
cd /var/www/dtpstat-wp-theme
python3 bin/generate-config.py --output /var/www/wp/wp-content/dtpstat-config.php --check
python3 bin/generate-config.py --output /var/www/wp/wp-content/dtpstat-config.php
php -l /var/www/wp/wp-content/dtpstat-config.php
```

Это отдельный файл **за пределами каталога темы**; `rsync --delete`
при выкладке темы его не трогает. Тема единожды подключает
`WP_CONTENT_DIR/dtpstat-config.php` через `require_once` и использует
константы `DTP_MAP_URL`, `DTP_FRONTEND_URL`, `DTP_CONTACT_*` и
`DTP_SOCIAL_*_URL`. PHP-код сайта никогда не парсит `.env`.
Изменения источника применяются только после повторной генерации и
обновления HTML/OPcache при необходимости.

Перед `rsync --delete` скрипт по SSH проверяет, что в целевом каталоге `wp-content` уже находится читаемый `dtpstat-config.php`. Если файл отсутствует, деплой прекращается **без изменения темы**.

`bin/deploy.sh` **не переносит** .env и не запускает генератор на
сервере: конфигурация целевого сайта должна быть подготовлена отдельно.
Подробности и порядок безопасной миграции — [SETUP.md](SETUP.md).

## Проверки

После развёртывания проверьте:
- наличие файлов в целевом каталоге;
- работающий PHP-рендер страниц;
- подключение стилей, JS и шрифтов;
- загрузку iframe и корректность запросов к API.

Скрипт `bin/verify.sh` — независимая проверка прежнего тестового стенда. Новый `bin/install.sh` не вызывает его; он также не является заменой тестирования продакшен-сайта после выкладки темы.
