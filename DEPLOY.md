# Выкатка

Запуск с рабочей машины:

```sh
./bin/deploy.sh
```

Скрипт rsync-ит `theme/dtpstat-child/` в каталог темы на WordPress-сервере
(`wp-content/themes/dtpstat-child`) и сбрасывает кэш WP. Тема уже активна — переключать
ничего не нужно; обновляется ровно один каталог, прочие установки WP скрипт не трогает.

Целевой сервер задаётся переменными в начале скрипта:

| Переменная | Смысл |
|---|---|
| `HOST` | ssh-алиас или адрес сервера |
| `WP_PATH` | каталог темы на сервере, от домашней папки |
| `WP_CLI` | команда вызова wp-cli на сервере (`~` и `$HOME` раскроются там же) |

## Окружение

Настройки темы (адрес фронтенда для айфреймов `DTP_FRONTEND_URL` и др.) живут на сервере
в `.env` рядом с WP-корнем и читаются в рантайме через `dtp_env()` — rsync их не касается,
смена = правка одной строки без пересборки.

## Айфрейм карты на главной

Зашит в контент WP-страницы (`front-page.php` выводит `the_content()` осознанно), на
`DTP_FRONTEND_URL` не реагирует. При смене адреса фронтенда правится в БД:

```sh
wp search-replace 'https://старый' 'https://новый' --dry-run
wp search-replace 'https://старый' 'https://новый'
```

Сначала смотреть `--dry-run`: если база общая с другим сайтом, замена затронет таблицы
только текущего префикса, но лишние совпадения лучше увидеть заранее.

## Установка с нуля и проверка

`bin/install.sh` и `bin/verify.sh` — запускать НА сервере (через ssh ломается `wp eval`),
см. README.
